## Summary

### Top 10 Critical
1. **Broken API surface — `/api/lume/*` routes do not exist.** `lume-detail-panel.tsx` and `lume-create-modal.tsx` call `/api/lume/customer`, `/api/lume/job`, `/api/lume/create-customer-and-job`; no router under `server/routes/` registers them. Every D2D map detail click → 404.
2. **`server/routes/cron.ts` is never mounted** in `server/index.ts`. Retention purge (`run_retention_job`) and audit purge (`purge_old_audit_events`) cannot be triggered — **compliance failure** (Loi 25 / LPRPDE data-retention obligations are documented but never enforced).
3. **OnboardingWizard step numbering inconsistency.** The "Back" button is gated `step > 0 && step < 2` (C:\Users\...\OnboardingWizard.tsx:366) — so on step 2 (Done) there's no back button (fine) but the **Skip label is rendered as empty string** on step 2 (`step === 2 ? '' : (t.onboarding.skip)` line 363), leaving an invisible button that still takes click focus and tab order. Stepper renders fine, but `handleSkip` on step 2 unexpectedly marks onboarding complete with no confirmation — user can lose progress with a stray Enter/Space press while the empty button is focused.
4. **OnboardingWizard `useEffect` missing deps + race.** L40-43: effect runs once with `[]` and calls `getCurrentOrgIdOrThrow()` to fill `resolvedOrgId`. If the user saves Company info before the promise resolves, `upsert` is called with `org_id: undefined` (silently swallowed in catch L86-88). The "Don't block onboarding if table doesn't exist yet" comment masks real data-loss.
5. **Onboarding flow has TWO disjoint implementations.** `OnboardingFlow.tsx` (8-step paid signup) and `OnboardingWizard.tsx` (3-step post-signup wizard) both write `company_settings` and both flip `profiles.onboarding_done`. They can race — a user finishing OnboardingFlow then immediately landing on the wizard re-prompts them. App.tsx:343-353 partially mitigates but only via a 5-minute timestamp window.
6. **`onboarding` step state not persisted in OnboardingWizard.** Unlike `OnboardingFlow` which mirrors every field into `sessionStorage`, the wizard loses all input on remount/refresh. Combined with the 200ms `getCurrentOrgIdOrThrow` race, refresh during onboarding can lose company info.
7. **Survey submission has no rate limit per token + no CSRF/origin check.** `/api/survey/:token` POST (L65) — anyone with a token can submit unlimited times until `submitted_at` is set. There is an IP rate limit on `/api/survey` (10/min) but a token replay across IPs is not blocked. Loi 25 data-integrity concern.
8. **`SUPABASE_SERVICE_ROLE`-equivalent confused naming in client code.** `src/lib/invoiceTemplatesApi.ts` and `src/lib/pipelineApi.ts` carry comments referencing "service_role — bypasses RLS" *inside the browser bundle*. These are explanatory comments, but they hint that older code shipped service-role to the client. Audit every `service_role` mention in `src/` to make sure none survive: confirmed clean in lib/, but the comments leak ops detail to anyone reading the source bundle. Remove.
9. **Service-role survey insert with no input ceiling on `feedback` length.** Survey POST stores `feedback` directly (L71-72) with no `.slice(maxlen)`. Feeds into `notifications.body` and `tasks.description` which then render verbatim in admin UI. Combined with hardcoded interpolation in the notification body (`Rating: 5/5. <user-text>`) it's stored-but-not-escaped — XSS-safe in React but logs and emails may render unsafely.
10. **`agent-auth.ts` JWT secret falls back to ephemeral random key.** L39 — if `AGENT_JWT_SECRET` env var is unset, a new random key is generated per process start. In a multi-replica deploy (Railway/Vercel scale-out) different replicas mint tokens the others cannot verify — random 401s. Should be a hard fail like `PAYMENTS_ENCRYPTION_KEY` is at index.ts:468.

## Critical bugs

### 1. Broken /api/lume/* API surface
- **Where**: `src/components/map-d2d/lume-detail-panel.tsx:46-47`, `src/components/map-d2d/lume-create-modal.tsx:128`
- **What**: Three fetch calls to endpoints that have no matching `router.get`/`router.post` in any file under `server/routes/`.
- **Repro**: Open D2D map, click on a pin → fetch returns 404, the panel shows "Impossible de charger les informations".
- **Why it matters**: D2D map pin detail UX is broken in production; users see only the error state.
- **Fix**: Either delete these two components (they appear unreferenced — see Dead code below) or create `server/routes/lume.ts` with the three handlers and mount it in index.ts.

### 2. Cron router never mounted — retention/audit purge never runs
- **Where**: `server/routes/cron.ts` exists but `server/index.ts` has zero `cron` references (grep verified).
- **What**: Two endpoints `POST /api/cron/retention` and `POST /api/cron/purge-audit` are inaccessible.
- **Why it matters**: Compliance Loi 25/LPRPDE/CCPA mandate timed deletion. `compliance_audit.md` references this cron, but it can never fire. Audit log will grow forever past the 1095-day retention.
- **Fix**: Add `import cronRouter from './routes/cron';` and `app.use('/api', cronRouter);` in index.ts, then wire an external scheduler (cron-job.org / Vercel Cron) to call it with `CRON_SECRET`.

### 3. OnboardingWizard race: org_id may be undefined when saving company
- **Where**: `src/components/OnboardingWizard.tsx:37-43, 56-92`
- **What**: `resolvedOrgId` defaults to `orgIdProp` (which arrives via App.tsx:178-181 from CompanyContext — may be `''` if loading). Effect resolves async; if user types fast and clicks Continue before the promise resolves, `upsert` runs with `org_id: undefined`, fails RLS, error swallowed silently (L86-88 `console.warn`+`return true`).
- **Why it matters**: Company info silently dropped; user reaches step 2 thinking it saved.
- **Fix**: Disable Continue button while `resolvedOrgId` is empty; OR throw a real error on missing org_id instead of swallowing.

### 4. OnboardingWizard Skip button on step 2 is invisible but tabbable
- **Where**: `OnboardingWizard.tsx:359-364`
- **What**: Renders `<button>{step === 2 ? '' : t.onboarding.skip}</button>` — empty text but still a focusable, clickable element.
- **Why it matters**: Keyboard tab order traps on a phantom button. Accidental Enter triggers `handleSkip` → flips `onboarding_done`. Confusing for accessibility tools.
- **Fix**: `{step !== 2 && <button ...>{t.onboarding.skip}</button>}`.

### 5. agent-auth JWT secret may be ephemeral
- **Where**: `server/routes/agent-auth.ts:39`
- **What**: `const JWT_SECRET = process.env.AGENT_JWT_SECRET || crypto.randomBytes(48).toString('base64');`
- **Why it matters**: Multi-replica deployment → cross-replica token verification fails. Production usually deploys ≥2 instances.
- **Fix**: Hard-fail at startup if `AGENT_JWT_SECRET` unset, matching the pattern at `index.ts:468-478` for `PAYMENTS_ENCRYPTION_KEY`.

### 6. `OnboardingFlow` stores raw password in sessionStorage
- **Where**: `src/pages/OnboardingFlow.tsx:117-118`
- **What**: `setPassword` writes `onb_pw` to sessionStorage.
- **Why it matters**: XSS or browser extension can read it; persists until cleared at L327.
- **Fix**: Don't persist password — re-prompt if user navigates away. Or replace persistence with a server-side session.

### 7. App.tsx auto-org-provision race
- **Where**: `src/App.tsx:303-360`
- **What**: Effect creates `orgs` + `memberships` if none exist. Two tabs after fresh signup both pass the `if (!mem)` guard and both create orgs.
- **Why it matters**: User stuck choosing between two empty workspaces; data fragmentation.
- **Fix**: Move org provisioning to server `/api/auth/register` (single-source). Add unique index on `memberships(user_id)` if "one org per fresh signup" is the rule, or use upsert with conflict on created_by.

### 8. `OnboardingFlow` redirect to attacker-controlled URL
- **Where**: `OnboardingFlow.tsx:726, 942`
- **What**: `window.location.href = data.url;` where `data` is the response JSON from `/api/billing/create-checkout-session`.
- **Why it matters**: If server is compromised or response is intercepted (mitigated by HTTPS), attacker can redirect to phishing site for credit card capture.
- **Fix**: Validate `data.url.startsWith('https://checkout.stripe.com/')` before assigning.

### 9. CompanyContext loading is shown to user in English-hardcoded
- **Where**: `App.tsx:180`
- **What**: `<div ...>Loading...</div>` — not translated.
- **Fix**: Use `t.common.loading` or similar i18n key.

### 10. Sidebar counter effect uses `setInterval(60s)` with no visibility pause
- **Where**: `App.tsx:511-524`
- **What**: Polls `quotes` and `invoices` count every minute regardless of tab visibility.
- **Why it matters**: Wastes battery + DB QPS for inactive tabs; multiplied by every logged-in user.
- **Fix**: Add `document.visibilityState === 'visible'` gate; or use Supabase realtime subscription.

## Bigger refactors (> 1 day)

### R1. Consolidate the two onboarding paths
`OnboardingFlow` (8-step paid) and `OnboardingWizard` (3-step post-paid) overlap heavily on `company_settings`, `onboarding_done`, org provisioning. A single state-machine driven by `profiles.onboarding_step` would eliminate the race in `App.tsx:303-360`.

### R2. Adopt a z-index scale
Replace ad-hoc `z-[80..9999]` with a named scale (`z-modal=100, z-toast=200, z-popover=50, z-overlay=40, z-cookie=300, z-command-palette=400`). Document in `tailwind.config.js` and `docs/ui-system.md`.

### R3. Migrate `/api/lume/*` and orphan map-d2d panels
Decide: kill them (delete files) or implement (create `routes/lume.ts` + reconnect to map-container click handler). Currently it's a hidden broken feature.

### R4. Replace `window.confirm` / `alert` / `prompt` with branded Confirm modal
30+ occurrences. Build a `useConfirm()` hook returning a Promise, use everywhere — better UX, screen-reader friendly, themable.

### R5. Wrap detail routes in `<TenantGuard>`
Currently only RLS protects cross-tenant ID access. Use the existing `TenantGuard` component for defense-in-depth on `/clients/:id`, `/jobs/:id`, `/quotes/:id`, `/invoices/:id`.

### R6. Move all `pages/*` direct `supabase.from()` calls into `src/lib/*Api.ts`
